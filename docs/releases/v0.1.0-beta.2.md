## What changed since beta 1

### Provider setup is guided now

Users can run:

```bash
img config setup
```

The flow guides provider selection, API-key entry, connection testing, model discovery, model selection, and persistence.

For agents and CI-style usage:

```bash
img --json config setup --provider ollama --api-key "$OLLAMA_API_KEY" --model minimax-m3
```

Non-interactive setup never prompts, returns machine-readable JSON, and fails loudly when required flags are missing.

### Models can be discovered before analysis

New model listing support uses provider metadata endpoints only:

```bash
img --json config models --provider ollama
```

It lists available model ids when the provider supports discovery and falls back to manual model entry when discovery is unavailable.

### Vision model guidance is safer

Model discovery now annotates known or likely image-capable models. Unknown or likely non-vision models warn without blocking, so the user remains in control while avoiding silent bad defaults.

### API keys are validated and redacted

Setting an API key now runs a connection test and reports typed failures without printing the key:

```bash
img config set providers.ollama.apiKey "$OLLAMA_API_KEY"
```

Secrets stay in user-scoped config and are redacted from stdout/stderr and test evidence.

### Doctor reports real provider readiness

`img doctor` now reports:

- runtime prerequisites
- active provider
- endpoint reachability
- selected model reachability
- actionable guidance such as `img config setup` when the configured model is unavailable

Use:

```bash
img --json doctor
```

### Provider errors are more actionable

Provider failures now distinguish auth, endpoint-not-found, model-not-found, malformed output, rate limit, timeout, and refusal paths where the provider response allows it.

Ollama Cloud default model was changed away from the unavailable `llama3.2-vision`; beta 2 uses the reachable `minimax-m3` default.

## Controlled beta 2 test plan

Run these in the cleaned beta test site after installing the new beta package:

```bash
img --version
img --json doctor
img --json config setup --provider ollama --api-key "$OLLAMA_API_KEY" --model minimax-m3
img --json config models --provider ollama
img --json doctor
img --json analyze CUSTOMER-IMAGES
```

Also validate invalid-key behavior:

```bash
img --json config setup --provider ollama --api-key invalid-key --model minimax-m3
```

Expected result: exit code `4`, typed auth failure, and no key material in output.
