# Smart Image CLI v0.3.0 Release Notes (candidate)

`0.3.0` is a prepared release candidate. The package version is bumped to `0.3.0` in-tree, but it is **not published, tagged, or released yet**. These notes describe the candidate relative to `0.2.0`.

## Highlights

- **Pixabay image source migrated and shipped.** The never-released Unsplash integration is fully removed and replaced by explicit Pixabay stock-photo sourcing via `smart-img pick --source pixabay`. Local remains the default; there is **no** automatic fallback either way.
- **Canonical `CUSTOMER-IMAGES` filesystem contract.** The managed working copy and the full `.img-ia/` + `_out/` path table are now documented as the stable layout. `analyze` may rename/move files inside the chosen root into category folders; use `--dry-run` to preview.
- **Credential and safety behavior locked down.** API keys (provider and Pixabay) never live in project config, argv, logs, cache, or error messages. Pixabay setup is interactive TTY only (`smart-img config pixabay setup`); missing credential → structured `missing_pixabay_credential` (exit 4), no HTTP.
- **Local source unchanged.** Local analyze, index, sidecars, listing, stats, optimization, picking, and usage tracking behave as in `0.2.0`. Ollama remains the only end-to-end validated analysis provider.
- **Verification expectations unchanged.** Use `npm test`, `npm run typecheck`, `npm run lint`, `npm run format`, plus `smart-img doctor` and `smart-img analyze` on real copied images.

## What is new

### Pixabay as an explicit image source

`--source pixabay` is an **explicit** external stock-photo path, separate from the local index.

- `local` is the default; `pixabay` is opt-in only. **No automatic local↔Pixabay fallback in either direction.**
- Credential precedence: `PIXABAY_API_KEY` env (operator override) **>** user-config `pixabay.apiKey` (set via private `smart-img config pixabay setup`).
- Search uses `image_type=photo` and `safesearch=true` by default (`--safesearch false` to disable).
- Per-project response cache under `.img-ia/pixabay/cache/` for 24h (cache identity excludes the key).
- One download per successful pick; already-used Pixabay ids for the same slot+location are skipped before download.
- **No upscale; no overwrite.** Free-tier cap may succeed with a structured `resolution_cap` warning instead of failing.
- Downloads are for combined-work / customer-website use only under the Pixabay Content License; no standalone redistribution.
- The Pixabay manifest is returned in CLI output, not persisted as a file.
- Full contract: [`docs/providers/pixabay.md`](../providers/pixabay.md).

Pixabay is an **image source**, not an AI vision provider. Only Ollama is end-to-end validated for image analysis.

### Unsplash fully removed

The never-released Unsplash integration (HTTP client, setup route/service, credentials, CLI source, and tests) is deleted. There is no migration path from Unsplash because it never shipped.

### Canonical filesystem contract

| Path | Created by | Purpose |
|------|-----------|---------|
| `<category>/` | `analyze` | Managed local library (organized images) |
| `.img-ia/config.json` | optional manual / `config set` | Project config; MUST NOT hold secrets |
| `.img-ia/index.sqlite` (+ WAL/SHM) | `analyze` | Derived queryable index (rebuildable from sidecars) |
| `.img-ia/sidecars/<sha>.json` | `analyze` | Durable per-image record (source of truth) |
| `.img-ia/usage.jsonl` | `pick` / `mark-used` | Usage journal (only after usage actions) |
| `.img-ia/pixabay/<id>.jpg` | `pick --source pixabay` | Downloaded Pixabay source |
| `.img-ia/pixabay/cache/<hash>.json` | `pick --source pixabay` | 24h search cache (key-stripped) |
| `.img-ia/pixabay/used-ids.jsonl` | `pick --source pixabay` | Used Pixabay ids per slot+location |
| `_out/<slug>[-NNN].<format>` | `optimize`, `pick` | Website-ready generated assets |

- `.img-ia/` is internal state; `_out/` is consumable output; `<category>/` dirs are the managed local library.
- Run against a narrow image-only root such as `./CUSTOMER-IMAGES` (the managed working copy), not the whole website.
- `CUSTOMER-IMAGES/` is the canonical managed working copy where the human/agent copies customer images for `smart-img`; it is not the customer's only/original source archive.
- No automatic local↔Pixabay fallback, no overwrite, no upscale, no automatic cleanup of generated/cached files.

## Customer image safety

- Treat customer originals as protected source material.
- For tests, copy a small sample into a sandbox first.
- Do not modify `CUSTOMER-IMAGES` unless the user explicitly chose that exact folder for organization.
- `analyze` may rename/move files inside the chosen root into category folders; use `--dry-run` to preview.

## Local analysis provider status (unchanged from 0.2.0)

- Ollama image analysis uses native `POST /api/chat`.
- `doctor` checks provider config, endpoint, model, and chat/inference readiness.
- `analyze` ignores common dependency/build/generated folders such as `node_modules`, `.git`, `dist`, `build`, `coverage`, `.next`, `.nuxt`, `vendor`, `.img-ia`, and `_out`.
- OpenRouter, Gemini, and other provider presets remain experimental until they pass install → configure → doctor → analyze on real images.

## Verification expectations

Before declaring `0.3.0` released, verify with real commands and report evidence:

```bash
npm test
npm run typecheck
npm run lint
npm run format
smart-img doctor
smart-img analyze "./CUSTOMER-IMAGES" --fail-fast
smart-img list "./CUSTOMER-IMAGES"
smart-img stats "./CUSTOMER-IMAGES"
```

Pixabay validation requires `PIXABAY_API_KEY` (operator env) or user-config `pixabay.apiKey` set via private `smart-img config pixabay setup`.

## Install / upgrade (after publication)

`0.3.0` is a candidate; it is not on npm yet. After it is published, install or upgrade with:

```bash
npm install -g smart-image-cli@0.3.0
smart-img --version
```

There is no upgrade-from-Unsplash path because Unsplash never shipped. Users coming from `0.2.0` keep the same local workflow and gain the opt-in `--source pixabay` path.

## Out of scope

- Thumbnail investigation is not shipped behavior in `0.3.0`.
- OpenRouter and Gemini remain unvalidated for image analysis.
- No automatic local↔Pixabay fallback, no upscale, no overwrite.
